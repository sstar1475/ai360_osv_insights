## 🎯 Ключевая концепция: Иерархия CWE

Вместо классических ML-подходов для семантической группировки используется **официальный граф MITRE**. 
Архитектура представляет собой направленный ацикличный граф (DAG) с 5-6 уровнями вложенности (Pillar -> Class -> Base и т.д.).

**Преимущества подхода:**
* Строгое и предсказуемое распределение уязвимостей по категориям.
* Возможность гибких запросов: пользователь может запросить срез как по верхнеуровневым абстракциям (Pillars), так и провалиться в дочерние типы конкретного CWE.
* Идеальная основа для построения сложных графов связей между типами уязвимостей и экосистемами.

---

## 📊 Базовые метрики и их расчет

Система оперирует набором ключевых метрик, которые проходят специальную математическую трансформацию для более объективной оценки при визуализации.

| Метрика | Описание | Логика подсчета / Трансформация |
| :--- | :--- | :--- |
| **Severity** | Критичность уязвимости (от 1 до 10). | **Экспоненциальная шкала**: `severity=1` считается как 1, `severity=10` — как 512 (например, по формуле `2^(S-1)`). Это подчеркивает реальную разницу между минорными и критическими багами. |
| **Patch Gap** | Время жизни уязвимости (дни между `introduced` и `fixed`). Парсится через GIT-коммиты в GitHub API. | **Логарифмическое сглаживание**: Разница между 1 и 30 днями критична, а между 1000 и 2000 — незначительна. Применяется логарифмирование малых значений. |
| **False Alarm Rate** | Процент отозванных/ложных уязвимостей. | Рассчитывается для выборки (например, только `severity=HIGH`), отозванной в течение заданных `k` дней. |
| **Unfixed Bugs %** | Доля неисправленных багов. | Считается в рамках конкретного пакета, целой экосистемы или специфического `pillar-cwe` типа. |

## 📈 Визуализация данных (Analytics Dashboard)

Инструмент поддерживает генерацию сложных аналитических графиков для поиска инсайтов в экосистемах:

### 1. Многослойные диаграммы (Stacked Bar Charts)
* **Сценарий:** Распределение уязвимостей по уровню `severity`.
* **Отображение:** Группировка внутри каждой экосистемы или внутри общего класса/pillar (в CWE-нотации). Общая высота столбца может отображать абсолютное количество объектов или быть нормализованной до 100% для оценки пропорций.

### 2. Диаграммы Сэнки (Sankey Diagrams)
* **Сценарий:** Визуализация "потока" уязвимостей.
* **Отображение:** Связи между CWE-ID (на уровне pillar или ниже) и экосистемами / популярными пакетами.
* **Фичи:** Цветовое кодирование потоков для разделения критичных (красные оттенки) и менее критичных (желтые/зеленые оттенки) уязвимостей.

### 3. Радарные диаграммы (Radar Charts)
* **Сценарий:** Сравнительный анализ пакетов или экосистем.
* **Отображение:** Выборка топ-$n$ пакетов по заданным осям метрик (например, Patch Gap, Severity Score, Unfixed %). Отлично подходит для парного или множественного визуального сравнения.

### 4. Связанный точечный график динамики (Connected Scatter Plot)
* **Сценарий:** Оценка развития экосистемы или топ-пакетов во времени.
* **Отображение (2D / 3D):** * **Ось X:** Количество новых уязвимостей/пакетов за квартал/год.
  * **Ось Y:** Средний показатель Patch Gap.
* **Динамика:** Временные промежутки (кварталы) соединены линиями, показывая "путь" пакета. Цвет вершин (узлов) отражает соотношение багов, починенных в течение следующих $x$ месяцев.
